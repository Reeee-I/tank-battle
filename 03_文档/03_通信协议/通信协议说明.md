# 通信协议说明

> 通用参数：**9600 bps、8 数据位、1 停止位、无校验**。所有帧**固定 3 字节**，
> 保证字节流按帧对齐。代码实现对照：PC 端 `02_上位机程序/serial_handler.py`，
> 板端各 `main*.c`（`01_下位机程序/` 下三套方案）。

## 1. 板 → PC 上行帧（按键包）

| 字节 | 含义 | 取值 |
|---|---|---|
| 0 | 包头 | `0xAA`（固定） |
| 1 | 玩家号 | `0x01`（玩家1）/ `0x02`（玩家2） |
| 2 | 按键掩码 | bit0 左(左转) · bit1 右(右转) · bit2 上(前进) · bit3 下(后退) · bit4 开火(K1,单发) · bit5 重开请求(K2,单发) · bit6 K3(单发,开始界面"任意键开始"用) |

- 方向键按住时**每 100ms 持续上报**（状态位方式）；K1 开火、K2 重开、K3 均为
  **按下瞬间单发一次**。
- 例：玩家1 按住"上"并按下 K1 → 发送 `AA 01 14`（0x14 = 0001_0100）。
- 不按键也定时上送（作心跳），PC 以 **0.6s 超时**判定断线。

## 2. PC → 板 下行帧（手柄 LED 血量联动，v2.8 起）

| 字节 | 含义 | 取值 |
|---|---|---|
| 0 | 包头 | `0xAA`（固定） |
| 1 | 下行命令码 | `0xD1`（玩家1 血量）/ `0xD2`（玩家2 血量） |
| 2 | 血量 | `0`~`3`（3 = 满血） |

- **LED 血条语义**（只作用于两块玩家手柄板）：满血3 = L0~L5 六灯全亮；
  每掉 1 血灭右侧 2 灯；死亡(0) = 全灭；上电到 PC 首次下发之间默认全灭。
  身份显示由数码管最左位（1/2）承担，LED 不再亮身份灯。
- **发送时机**：开局（满血）、每次命中扣血、血包回血、死亡归零、K2/鼠标重开复位；
  板子中途重插/重连自动补发一次当前血量。
- **发送路径**：① 有线 USB 直连 = PC 写各玩家绑定 COM；
  ② 485 = PC 写**中转板** COM（单口含 D1/D2 两帧），中转板在总线空闲窗口转发给
  对应手柄；③ 红外无线本期**不支持**（HEX-A 无下行通道，LED 保持全灭属正常）。

## 3. 485 板间轮询协议（手柄 ↔ 中转板，对 PC 透明）

半双工，9600bps 8N1，所有帧固定 3 字节：

| 方向 | 帧内容 | 说明 |
|---|---|---|
| 中转板 → 手柄1 | `AA E1 00` | 点名玩家1（0xE 前缀与玩家号 01/02 永不冲突） |
| 中转板 → 手柄2 | `AA E2 00` | 点名玩家2 |
| 手柄1 → 中转板 | `AA 01 mask` | 应答，**与 PC 协议完全一致** |
| 手柄2 → 中转板 | `AA 02 mask` | 同上 |
| 中转板 → 手柄1 | `AA D1 HP` | 下行血量帧，空闲窗口转发 |
| 中转板 → 手柄2 | `AA D2 HP` | 下行血量帧，空闲窗口转发 |

**时序**（中转板每 100ms 一个周期，10ms 事件超时计数，全部非阻塞）：
t=0 点名 P1 → 收到应答即转发并点名 P2（无应答 30ms 后也点名 P2）→ 收到 P2 应答转发，
周期结束。单块手柄掉线不阻塞另一玩家。

- 点名码 E1/E2、血量命令码 D1/D2 与按键帧 `AA 01/02 xx` **永不撞帧**；
- 各板按帧第 2 字节过滤：他人点名/应答/血量帧直接丢弃，不会误应答/误转发；
- 参数集中在 `01_下位机程序/02_RS485模式/main_hub.c` 顶部
  （`P1_WAIT_TICKS=3`→30ms、`P2_WAIT_TICKS=4`→40ms、`DL_SEND_TICKS=2`→空闲≥20ms）。

## 4. 红外无线方案（与有线协议完全一致）

- HEX-A（发射端）每 100ms 采集一次并发送 `AA 02 xx`（固定玩家2），
  K1/K2/K3 按下瞬间单发；不按键也发（心跳）；
- HEX-B（接收端）收到后**原样**转发 3 字节，不做任何改动；
- HEX-A 关机/移出范围 → HEX-B 收不到就不发 → PC 0.6s 心跳超时判玩家2"断开!"。

## 5. 蓝牙无线方案（BT05 BLE 桥接，当前正式路线；帧与有线协议完全一致）

- 板端每 100ms 发送 `AA 01/02 mask`（同其它方案），蓝牙**全双工透传**，
  故下行血量帧 `AA D1/D2 HP` 同样支持（LED 血条 + 命中/结束音效，游戏实测通过）；
- BT05 为 BLE（CC2541），Windows 无虚拟 COM → PC 端经
  `02_上位机程序/tools/ble_bridge.py`（bleak）+ VSPD 虚拟串口对（COM20/21）
  把 BLE 字节流呈现为普通 COM 给游戏，游戏**零改动**（`--p1/--p2` 指定 COM20）；
- 过滤与绑定规则不变：PC 按包第 2 字节（玩家号）自动绑定；蓝牙一板一链路无冲突；
  断连由 0.6s 心跳判定，恢复自动重连。

## 6. 协议常量的代码位置

| 常量 | 定义处 |
|---|---|
| `PKT_HEADER` / `PKT_P1` / `PKT_P2` / 按键位掩码 | 各板 `main*.c` 顶部宏区 |
| `POLL_P1`(0xE1) / `POLL_P2`(0xE2) / `DL_HP_P1`(0xD1) / `DL_HP_P2`(0xD2) | `02_RS485模式/main_handle.c`、`main_hub.c` |
| PC 侧解析 / 组包 / 自动绑定 / 断线判定 | `02_上位机程序/serial_handler.py` |
| 下行发送时机（开局/命中/回血/死亡/重开/重连补发） | `02_上位机程序/game.py` + `serial_handler.py` |
