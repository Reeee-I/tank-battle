## 一、整理前结构与存在的问题

整理前根目录结构（示意）：

```
A大项目/
├── README.md、开发计划.md、UI重设计计划.md、验收复测清单.md     ← 文档散落在根目录
├── STC_B_BSP_V3.6b_API参考.md / STC_B_BSP_Ver3.6b_文档原文.txt / STC_B学习板BSP说明.docx
├── inc/                          ← 与 MCU/inc/ 完全重复的 BSP 头文件
├── MCU/                          ← 有线 USB 方案工程（含 sound_effect 副本、inc、STC_BSP.lib）
├── 485手柄/                      ← RS485 三工程（含 sound_effect 副本）
├── 无线手柄/HEX_A_IR_Tx、HEX_B_IR_Rx   ← 红外发射/接收工程（含 inc、STC_BSP.lib、sound_effect 副本）
├── sound/                        ← 音效模块 + 4 份与正式源完全相同的 main 副本 + 2 份说明
├── PC/                           ← PC 端程序
├── picture/                      ← UI 素材（无扩展名）
└── HEX/                          ← 统一 HEX 输出目录（本次保持原样）
```

主要问题：
1. 多个功能独立的目录平铺在根目录，无"上位机 / 下位机 / 文档"总分类；
2. **大量重复副本**：BSP 头文件（4 份 inc）、`STC_BSP.lib`（3 份）、
   `sound_effect.c/h`（4~5 份）、4 个"音效版 main"（与正式源逐字节相同）；
3. 文档（README、计划、BSP 参考）散落根目录，无统一文档体系；
4. 上位机素材（picture/）与运行代码混在根目录。

## 七、后续开发请遵守的目录规则（防止再次混乱）

**归类规则**
- `.c/.h`：按所属方案放 `01_下位机程序/0X_*模式/`；**可复用、多方案共享**的代码
  一律进 `01_下位机程序/common/`（含 `common/inc/` 头文件、`STC_BSP.lib`）。
- 音效相关源码只维护 `01_下位机程序/04_音效模块/` 一份，工程引用它，**禁止再复制**。
- `.py`：一律放 `02_上位机程序/`（含新模块）；测试放 `02_上位机程序/tests/`。
- `.md/.txt/.docx` 文档：一律放 `03_文档/` 对应子目录；**根目录只保留一个 README.md**。
- `.hex`：只放根目录 `HEX/`，Keil Output 目录指向它，不在别处另存。
- `.uvproj/.uvopt`：跟随其 `main*.c` 所在方案目录。
- 素材（图片等）：放 `02_上位机程序/素材/`（PC 用）等归属明确处，不放根目录。

**命名规则**
- 一级目录用 `01_ / 02_ / 03_` 数字前缀控制排序 + 中文名；
- 子目录/文件用下划线分词；新建方案沿用现有编号规律（先查是否已有同类方案）。

**工程配置规则（新建 Keil 工程）**
- Include Paths = `..\common\inc;..\04_音效模块`（更深一层目录则 `..\..\`）；
- 添加 `..\common\STC_BSP.lib`；要音效就加 `..\04_音效模块\sound_effect.c`；
- Output Directory 指向 `HEX/`（一层目录 `..\..\HEX\`，两层 `..\..\..\HEX\`）。

**文档约定**
- 每次改动在 `03_文档/05_开发日志/开发日志.md` 记一条；重要设计决策同步到
  `03_文档/04_项目计划/开发计划.md`；
- 新写说明优先放入对应模块的 `README.md`（随代码走）或 `03_文档/` 分类目录。
