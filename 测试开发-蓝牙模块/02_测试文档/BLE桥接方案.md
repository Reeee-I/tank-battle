# BLE 桥接方案（BT05 模块 → 虚拟串口 → 游戏）

> 适用：手头蓝牙模块是 **BT05（CC2541 BLE 透传模块，0xFFE0/0xFFE1）** 时，
> 用"BLE 桥接 + 虚拟串口对"让**既有游戏零改动**联机。这是对
> `接线与模块配置.md / 联调与验收步骤.md` 中"经典蓝牙 HC-05/06"路线的替代方案。

## 为什么需要桥接

- BT05 是 **BLE（低功耗蓝牙）**，Windows **不会**为它创建任何 COM 口（只有
  经典蓝牙 SPP 才有虚拟 COM）；所以在"蓝牙设置/COM 端口"里怎么都找不到它。
- 但我们已实测：PC 用 **bleak** 连接 BT05，订阅 0xFFE1 通知，能稳定收到手柄板
  每 100ms 一帧的 `AA 01 xx`（上行链路完全可用）。
- 方案：**com0com 虚拟串口对**（COM_A ↔ COM_B）+ 桥接程序 `ble_bridge.py`：
  游戏打开 COM_A（pyserial 普通 COM，代码零改动）；桥接程序打开 COM_B，
  把字节流双向搬运到 BLE。**对游戏而言它就是一个普通串口手柄。**

```
 [蓝牙手柄板]                    PC（笔记本）
  按键 → UART2(EXT)              ┌──────────────────────────────────────┐
      → BT05(BLE 0xFFE0/FFE1)    │ bleak ←→ ble_bridge.py ←→ COM_B        │
      ←←←←← BLE 无线 ←←←←←←←←←←←│        （com0com 虚拟对）               │
                                │ COM_A ←→ 游戏 main.py --p1 COM_A        │
                                └──────────────────────────────────────┘
```

## 一、安装 com0com（虚拟串口对，需管理员）

安装包已下载解压在：`03_测试工具/com0com_x/`
（`Setup_com0com_v3.0.0.0_W7_x64_signed.exe`）。

1. 在文件管理器里找到该 exe → **右键 → 以管理员身份运行**（UAC 点"是"）；
2. 向导一路 下一步 → 安装 → 完成；
3. 验证：开始菜单出现 **com0com**（COM0COM 控制台），或
   设备管理器出现 **com0com 串口端口（COM/COM）** 设备。

## 二、建立虚拟串口对（COM20 ↔ COM21）

打开 **com0com Control Center（COM0COM 控制台）**：
1. 默认已有一对端口（通常 `CNCA0`、`CNCB0`）；
2. 分别点选每个端口 → **改名为 COM20 / COM21**（改名后点 Apply/应用）；
   > 若列表为空：菜单/按钮里 **Add Pair（添加成对端口）** 先加一对，再改名。
3. 确认状态栏显示 **COM20 ↔ COM21 已连接**。

> 端口号可自选（避开现有 COM3/4/5/7/8 即可）。游戏与桥接各占一头，顺序无所谓：
> 下文示例 = 游戏 `--p1 COM20`，桥接 `--com COM21`。

## 三、启动桥接程序

打开一个新命令行窗口：

```bat
cd C:\Users\孙明哲\Desktop\暑期实训\A大项目
python 测试开发-蓝牙模块\03_测试工具\ble_bridge.py --com COM21 --addr 00:15:83:F0:15:97 --debug
```

预期日志：
```
[时间] 桥接启动：BLE 00:15:83:F0:15:97 <-> 串口 COM21（给游戏用另一侧 COM）
[时间] 串口 COM21 已打开
[时间] 扫描/连接 BLE …
[时间] BLE 连接成功
[时间] 透传通道: 0000ffe1-…（notify,read,write,write-without-response）
[时间] notify 已开启 → 串口方向就绪
[时间] BLE→COM: aa 01 00 aa 01 00 …（每 100ms 一帧，--debug 时逐帧打印）
```

> 如果卡在"扫描/连接"：
> - 把**蓝牙手柄板断电几秒再上电**（BT05 上电后才广播，桥接才能扫到并连接）；
> - 若之前配过对：设置→蓝牙和其他设备→把 BT05 **删除设备**，再断电重启板子；
> - 也可先 `python 测试开发-蓝牙模块\03_测试工具\ble_bridge.py --scan`
>   确认能扫到 `BT05 / 00:15:83:F0:15:97`。

## 四、启动游戏（PC 端零改动，只加参数）

**再开一个**命令行窗口：

```bat
cd C:\Users\孙明哲\Desktop\暑期实训\A大项目\02_上位机程序
python main.py --p1 COM20 --p2 COM4
```

- `--p1 COM20` = 蓝牙手柄（经桥接）；`--p2 COM4` = 那块有线玩家2板
  （当前插在电脑上、会发 `AA 02` 的那块；若它没插，可改用键盘当玩家2）。
- 预期：画面顶部玩家1出现绿点并保持在线；开始界面按蓝牙板任意键进入；
  移动/转向/开火跟手；拔蓝牙板电源约 0.6s 后玩家1显示"断开!"，恢复上电自动重连。

## 六、日常使用（以后每次怎么跑 —— 2026-09-06 游戏实测通过版）

> 结论：这套 BT05/BLE 路线**不是纯"插上就用"**——每次需要 3 步；已做成
> 一键脚本 `测试开发-蓝牙模块/启动蓝牙对战.bat`（双击即可，含等待链路）。

| 步骤 | 动作 | 说明 |
|---|---|---|
| 0 | 给蓝牙板上电（USB 供电，不插电脑数据线） | 板数码管亮；模块上电后广播约数十秒 |
| 1 | **双击 `启动蓝牙对战.bat`** | 自动做：开桥接窗口 → 等链路 OK（≤45s）→ 启动游戏 |
| 2 | 若 45 秒没连上 | 把蓝牙板**断电 3 秒重上电**，再重跑 bat（模块休眠是老脾气，非故障） |
| 3 | 游戏内操作 | 玩家1=蓝牙手柄（导航键/K1/K2），玩家2=有线板 COM4（或键盘） |

手动三步（不用 bat 时）：
```bat
:: 窗口1：桥接（保持运行）
python 测试开发-蓝牙模块\03_测试工具\ble_bridge.py --com COM21 --addr 00:15:83:F0:15:97
:: 窗口2：游戏
cd 02_上位机程序
python main.py --p1 COM20 --p2 COM4
```

日常注意：
- **VSPD 的 COM20/COM21 与驱动开机自启**，一般不用重设（若哪天串口列表里没了，
  打开 VSPD 主界面重新 Apply 一次）；com0com 已停用，留着不影响。
- 若桥接窗口长时间"扫不到模块"：先试断电重上电板子；还不行就在
  设置→蓝牙和其他设备 里把 BT05 **删除设备**再重上电板子
  （Windows 偶发把它重新配对后会不再广播）。
- 正式路线仍是 HC-05/HC-06 经典蓝牙（届时无需桥接/VSPD，流程更简）。

## 常见问题

| 现象 | 处理 |
|---|---|
| 桥接卡在"扫描/连接" | 蓝牙手柄板断电重上电（模块重新广播）；删除 Windows 里旧配对 |
| 打开 COM20 报"打不开/被占用" | com0com 对没建好或名字没生效：重开 COM0COM 控制台核对 COM20/COM21 |
| 桥接报串口打不开 | 确认 --com 填的是 com0com 的 **B 侧**（游戏用另一侧） |
| 游戏自动扫描找不到玩家1 | 必须 `--p1 COM20` 显式指定（自动扫描跳过蓝牙口属既有设计） |
| 桥接收到帧但游戏不认 | 确认游戏用的 COM 与桥接用的 COM 是**同一对**（A/B 两侧） |
| 频繁断线 | 缩短板与电脑距离；排除遮挡；必要时换一个 USB 口插板供电 |

## 已知环境坑：com0com 驱动在 Win11 25H2 被签名策略拒绝（2026-09-06 实测记录）

现象：`sc start com0com` 报 **577：Windows 无法验证此文件的数字签名**，
COM20/COM21 永不出现。原因：本机为 **Windows 11 25H2（build 26200）**，
内核只接受新式认证/WHQL 签名驱动；com0com 3.0.0.0（2016 年老签名）被拦。
已尝试：关闭"内存完整性(HVCI)"→ 无效；服务为 DEMAND_START，手动启动仍 577。

三条出路（按推荐序）：
1. **换正式路线 HC-05/HC-06 经典蓝牙模块**（推荐，即本项目正式方案）——
   经典 SPP 直接生成 Windows COM，**完全不需要 com0com/桥接程序**；
2. **一次性禁用驱动签名后加载 com0com**（仅测试期够用）：
   设置→系统→恢复→高级启动→立即重新启动 → 疑难解答→高级选项→启动设置→
   重启 → 按 **7**（禁用驱动程序强制签名）→ 进桌面后管理员运行
   `sc start com0com`（效果仅本次开机，正常重启即恢复，不动系统设置）；
3. **VSPD（Eltima）试用版**：微软 WHQL 签名、25H2 可直接装，建 COM20/COM21 对。

> 备注：BLE 上行链路本身（板→BT05→PC，`AA 01` 每 100ms）已实测打通，
> 见 `测试开发-蓝牙模块/README.md`；卡点仅在"PC 侧最后一步：把 BLE 字节流
> 呈现为游戏可打开的 COM 口"——属 Windows 驱动签名策略问题，非设计问题。
