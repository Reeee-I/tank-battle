# 蓝牙手柄 · 联调与验收步骤（测试开发）

> 前置：已完成 `测试开发-蓝牙模块` 全部固件/工程准备；两块板烧好
> `HEX\BT_Player1.hex` / `HEX\BT_Player2.hex`（STC-ISP：STC15F2K60S2、
> 11.0592MHz，烧完关闭 STC-ISP）；接线与配对按《接线与模块配置.md》完成。
> 测试全程**不改动任何既有文件**；PC 端只用既有程序的 `--p1/--p2` 参数。

## 阶段 A：单块板裸链路自测（不开游戏）

1. 只给 **1 块蓝牙手柄板**（比如玩家1，BT_Player1.hex）上电；
2. 记录它的蓝牙 COM（如 `COM6`）；
3. 监听：
   ```bat
   cd 02_上位机程序
   python tools/serial_probe.py COM6
   ```
   预期：
   - 每 100ms 打印一帧 `玩家1 mask=0x00`（不按键也发 = 心跳）；
   - 按住导航"上"→ `mask=0x04`；同时按"上+K1"→ `0x14`（其余键同理对照协议）；
   - 按 K1 开火、K2、K3：对应 bit4/bit5/bit6 只在按下瞬间出现一次；
   - 关板电源 → 停止收帧（对应上位机 0.6s 心跳判离线）；恢复上电 → 自动恢复收帧。
4. **通过标准**：上述全部符合，且无乱码帧/丢帧抖动。

## 阶段 B：单块蓝牙板进游戏（首测拓扑：一蓝牙 + 一既有板）

- 玩家1 沿用**有线板**（USB 直连，或 485 中转板），玩家2 用**蓝牙板**。例：
  ```bat
  cd 02_上位机程序
  python main.py --p1 COM3 --p2 COM6
  ```
  （`--p1/--p2` 必须同时给出两块板的 COM：preferred 模式下只打开指定口。）
- 验收点：
  - [ ] 开始界面：蓝牙手柄按任意键可开始（K3 / K1 / 方向均可）；
  - [ ] 玩家2 移动/转向/开火跟手、无卡顿感（100ms 上报与有线一致）；
  - [ ] 对局结束按 K2 可重开；Esc/鼠标正常；
  - [ ] **只拔蓝牙板电源**：约 0.6s 后画面显示玩家2"断开!"，**玩家1 正常不受影响**；
  - [ ] 重新给蓝牙板上电：自动重连，玩家2 恢复操控（无需重启游戏）；
  - [ ] 两板数码管各显示 1 / 2，LED 均随血量变化（见阶段 C）。

## 阶段 C：下行 LED 血量验证（蓝牙全双工支持项）

> 蓝牙链路全双工，下行血量帧可直达手柄板（优于红外方案）。若无 RXD2 引出则整段降级跳过。

方式一（对局内观察）：
- [ ] 开局下发满血：玩家2 蓝牙板 L0~L5 **六灯全亮**；
- [ ] 被击中扣血：每掉 1 血灭右侧 2 灯（3→2→1→0 对应 6/4/2/0 灯）；
- [ ] 死亡归零：全灭并响"游戏结束"下扫音；被击中瞬间有"呜"低鸣；
- [ ] 回血（血包）：灯数回升；
- [ ] 蓝牙板**中途断电重连**：重连后首包到达时 PC 自动补发当前血量，LED 立即恢复正确。

方式二（独立验证，不开游戏）：
```bat
cd ..\测试开发-蓝牙模块\03_测试工具
python send_led_hp.py --list
python send_led_hp.py --port COM6 --player 2 --hp 3
python send_led_hp.py --port COM6 --player 2 --hp 0
python send_led_hp.py --port COM6 --player 2 --hp 3 --repeat 3   :: 同值重发不重复响
```

## 阶段 D：双蓝牙板并行

1. 两块板都上电并各自完成蓝牙连接，确认设备管理器里两个蓝牙 COM（如 COM5/COM6）；
2. ```bat
   cd 02_上位机程序
   python main.py --p1 COM5 --p2 COM6
   ```
3. 验收点：
   - [ ] 两块板自动按包内容绑成玩家1/玩家2（**COM 与玩家对应关系无须记，绑错自动纠正**）；
   - [ ] 双人同时操作互不干扰、无互相断线；
   - [ ] 关任意一块板只影响对应玩家（0.6s 显示断开），另一玩家继续正常对局；
   - [ ] 恢复上电自动重连，血量 LED 自动补发正确。
