# 蓝牙手柄 · 接线与模块配置（测试开发）

> 适用：`测试开发-蓝牙模块` 的蓝牙手柄方案。板子 = STC-B 学习板
> （STC15F2K60S2），蓝牙模块 = UART 透传型（HC-05 / HC-06 或兼容品，暂未定型号，
> 本文按这两类覆盖；其它型号按实物说明书核对）。协议仍为 **9600bps 8N1**。

## 一、系统组成

```
[蓝牙手柄板]        UART 透传         [笔记本自带蓝牙]       [上位机 Python 游戏]
 STC-B 学习板   ────────蓝牙────────→  虚拟 COM (COMx)  ────→  main.py --p1/--p2
  EXT口 UART2        (SPP)             "标准串行 over 蓝牙"
  9600 8N1 全双工                       9600 8N1
   板载USB仅供电（充电头/充电宝，不接电脑数据）
```

- 每块手柄板 = 一个蓝牙模块 + 一条独立链路 + 一个虚拟 COM（与有线 USB 直连的两 COM 形态一致；
  PC 端按包内容自动绑玩家，无需记忆 COM 与玩家的对应关系）。
- 蓝牙是**全双工透传**：上行按键帧、下行血量帧（LED 血条 + 音效）都走同一链路。

## 二、板 ↔ 模块接线（杜邦线，交叉连接）

| 蓝牙模块引脚 | 接到开发板 | 说明 |
|---|---|---|
| RXD（收） | 板 **TXD2（P1.1）** | 模块收 = 板发 |
| TXD（发） | 板 **RXD2（P1.0）** | 模块发 = 板收；引脚位置以板面丝印为准 |
| GND | 板 **GND** | **必须共地** |
| VCC | 板 **+5V** | HC-05/06 常见 5V 供电（带板载稳压），以模块说明书为准 |

要点：
- 板端走 **EXT 扩展口串口2（TTL）**，这是 STC-B BSP 官方支持"外接蓝牙模块"的通道
  （BSP 说明见 `03_文档/07_参考资料/`，uart2 模块：`Uart2UsedforEXT`）。
- 板上电后数码管最左位显示 **1 或 2**（玩家身份），LED 默认全灭。
- 若你的板面 **只引出 TXD2、没有 RXD2**：下行血量帧收不到（LED 恒灭），
  但上行按键遥控完全正常——等同既有"纯上行"接法，不算故障，验收时把下行项降级即可。

## 三、板供电与上电顺序

1. 两块手柄板板载 USB 接**充电头/充电宝**（仅供电）。不要插电脑数据口——
   否则板载 CH340（串口1）那一路会多出 USB COM，干扰"只留蓝牙 COM"的测试环境。
2. 顺序建议：先开笔记本蓝牙 → 再给手柄板上电（模块随之通电并尝试连接）→
   确认电脑里出现并"已连接"的蓝牙 COM → 再启动游戏/测试工具。
3. 烧录固件时例外：用 STC-ISP 走板载 USB 烧录，烧完**关闭 STC-ISP**再改回充电供电。

## 四、模块配置（AT / 波特率核对）

> 协议固定 9600 8N1 —— **改模块，不改协议**。

- **HC-05（从机角色，推荐）**：按住模块上按键上电进入 AT 模式（LED 慢闪），
  电脑用 USB-TTL/板载串口以 **38400 8N1** 发送 AT 指令（每指令回车结尾）：
  | 目的 | 指令 | 说明 |
  |---|---|---|
  | 改名（区分两块） | `AT+NAME=TB_P1` / `AT+NAME=TB_P2` | 配对列表里好认 |
  | 从机角色 | `AT+ROLE=0` | 由电脑侧发起连接 |
  | 波特率 9600 | `AT+UART=9600,0,0` | 0 停止位? 实际含义：9600,停止位0=1位,校验0=无 |
  | （可选）配对码 | `AT+PSWD=1234` | 默认多为 1234 |
  改完断电重上电退出 AT 模式。
- **HC-06（从机透传）**：多数出厂即 **9600 透传、免配置**，直接接线配对即可。
  若默认波特率不是 9600（个别固件需 AT 改），按其手册把模块设到 9600。
- **其它型号**：按实物说明书核对"透传波特率=9600、8N1"与"从机可被发现"。
- **核对办法**：配好对后跑
  `cd 02_上位机程序 && python tools/serial_probe.py COMx`
  应每 100ms 看到一帧 `AA 01/02 mask`。若乱码/无帧：先查波特率与接线。

## 五、PC 配对与 COM 识别（笔记本自带蓝牙，Windows 10/11）

1. 设置 → 蓝牙和其他设备 → 打开蓝牙 → 添加设备 → 蓝牙；
2. 给蓝牙手柄板上电，列表出现模块（改名后如 `TB_P1`/`TB_P2`）→ 点击配对；
   配对码提示时输入 `1234`（HC-05/06 常见默认，若不对看模块资料）；
3. 配对成功后看 **设备管理器 → 端口(COM 和 LPT)**，找到
   **"Standard Serial over Bluetooth link (COMx)"** 或
   **"标准串行 over 蓝牙链接 (COMx)"** —— 这就是上位机要用的虚拟 COM；
   两块板各一个 COM（可能是"传出"也可能"传入"，都能用，见下）；
4. 若配对后**没有出现 COM**：打开 设置 → 蓝牙和其他设备 → 更多蓝牙选项 →
   **COM 端口** 选项卡 → 添加 → 方向选**传入（设备发起连接）** → 确定，
   然后把该 COM 关联到对应已配对模块（Windows 会列出可绑定设备）；
   重新连接/重启蓝牙后再查设备管理器。

常见坑（FAQ）：
- 启动游戏提示打不开某 COM / 卡住：先确认该模块**已连接**（蓝牙设置里显示已连接、
  设备管理器该 COM 存在）再启动；传入型 COM 在模块没连上时打开会等待。
- 两个模块都叫 HC-05 分不清：靠 AT 改名；即便 COM 对调也不影响对局——
  PC 按数据包里的玩家号自动绑定（哪块发 `AA 01` 就是玩家1）。
- 配对过一次后开机不自动连：手柄板断电重上电即可触发模块重新连接电脑。
- 距离/遮挡导致断流：桌面 1~5 米内无遮挡即可；发现丢包先缩短距离验证。

## 六、验证命令速查（本方案不用改任何既有 PC 代码）

```bat
cd 02_上位机程序
python tools/serial_probe.py COM6              :: 裸监听某蓝牙 COM（链路自测）
python main.py --p1 COM3 --p2 COM6             :: 混合：玩家1 有线板 + 玩家2 蓝牙板
python main.py --p1 COM5 --p2 COM6             :: 双蓝牙
cd ..\测试开发-蓝牙模块\03_测试工具
python send_led_hp.py --list                    :: 查看全部串口（含蓝牙）
python send_led_hp.py --port COM6 --player 2 --hp 3   :: 下发满血帧验证 LED
```

> 为什么必须显式指定 COM？PC 自动扫描会跳过蓝牙虚拟 COM（既有设计，避免误开未连接
> 的蓝牙口），而 `--p1/--p2` 手动指定路径不受该过滤影响——**这是既有功能，不是改动**。
