## 3. 系统连接图（无线方案：玩家2 走红外，PC 端零修改）

```
[HEX-A 发射板]     红外(38KHz NEC)      [HEX-B 接收板]       串口1(USB)       [PC 游戏]
玩家2无线手柄   ───────────────────→  IR_RXD 收包校验    ──────────────→  自动绑定为玩家2
(导航键+K1/K2)    IR_TXD → IR_RXD       AA 02 xx 原样转发  9600 8N1       无需改代码
    每100ms一包                                                (板载USB/CH340)
```

- **玩家1** 仍用原有线手柄板（`HEX\USB_Player1.hex`，原接线不动）。
- **玩家2** 用本模块：HEX-A 无线发射 + HEX-B 接收转发，替代原玩家2有线板
  （原玩家2有线板与 `USB_Player2.hex` 不再需要接入电脑）。
- PC 端 `serial_handler.py` 按数据包内容自动绑定：哪个 COM 先发来 `AA 02 xx`
  合法包，就绑定为玩家2 —— 因此 **PC 端代码一行都不用改**。

## 4. 通信协议（与现有有线协议完全一致）

3 字节数据包，**9600 bps（转发侧）、8 数据位、1 停止位、无校验**：

| 字节 | 含义 | 取值 |
|---|---|---|
| 0 | 包头 | `0xAA`（固定） |
| 1 | 玩家号 | `0x02`（固定玩家2） |
| 2 | 按键掩码 | bit0 左 · bit1 右 · bit2 上 · bit3 下 · bit4 开火(K1,单发) · bit5 重开请求(K2,单发) · bit6 K3(单发,开始界面"任意键开始"用) |

- HEX-A 每 **100ms** 由 `enumEventSys100mS` 定时回调采集一次按键并发送
  （不按键也发，作心跳，PC 靠它判定在线）；
- K1 开火 / K2 重开请求 / K3 为"按下瞬间单发"：只在发送请求被 IR 模块接受后清除标志；
- HEX-B 收到后**原样**转发 3 字节，不做任何改动；
- HEX-A 关机/移出红外范围 → HEX-B 收不到就不发 → PC 端 0.6s 心跳超时显示
  玩家2"断开!"并冻结其输入（与现有有线断线逻辑一致）。

## 5. 快速上手（三步）

1. **烧录两块板**（详见各工程 README）：
   - 把 `HEX\IR_Player2.hex` 烧进"玩家2无线手柄板"（发射端，数码管 A）；
   - 把 `HEX\IR_Relay.hex` 烧进"接收转发板"（数码管 b，接电脑 USB）。
2. **接线**：HEX-A 板载红外发射管（IR_TXD）对准 HEX-B 板载红外接收管
   （IR_RXD），距离 0.2~3 米、中间无遮挡；HEX-B 用板载 USB 线连电脑；
   HEX-A 供电可用任意 USB 口（5V），不需连电脑。
3. **开游戏**：`cd PC && python main.py`（或 `--p1 COMx` 手动指定玩家1口）。
   上电顺序建议：先 HEX-B（转发板），再 HEX-A（手柄），PC 会自动把 HEX-B
   所在 COM 绑定为玩家2。

> 对局结束后，无线手柄同样可 **按 K2 请求重开**（bit5，PC 结算画面处理），
> 与原有线手柄行为一致。
>
> 开始界面：按 **K1 / K2 / K3 / 导航键任意一键** 均可进入对战（bit6=K3 于 v2.6 加入，
> 需重新烧录 `IR_Player2.hex`）。

## 6. 兼容性与注意事项

1. **PC 端、原工程代码均无需修改**；新增内容全部在本目录内。
2. 两份 BSP 库/头文件为副本，与 `MCU/` 内原件内容一致（V3.6b）。
   若日后替换库版本，请同时替换本目录两个工程内的副本与 `inc/` 头文件，
   保持同版本。
3. IR 通信为 **单工、无校验**：HEX-B 靠"长度=3 + 包头 AA + 玩家号 02"
   过滤干扰（普通家电遥控器多为 4 字节 NEC 帧，会被自动丢弃）。
4. 红外易受阳光/强光与遮挡影响，请保持发射/接收管对正、无遮挡；
   发射管是方向性器件，必要时用胶带固定两板对准。
5. `SysClock=11059200`，烧录时 STC-ISP 频率选 **11.0592MHz**（外部晶振），
   与板端一致；否则所有定时（100ms 心跳、红外时序）都会偏移。
6. 两工程编译结果中出现的 `WARNING L16: UNCALLED SEGMENT` 为 Keil 对库中
   未调用段的常规提示，与原工程一致，**不是错误**，可忽略。
7. 四工程共用 `A大项目\HEX\` 一个输出目录（Keil 中此目录内 `main.obj` 等
   为中间产物可忽略/删除，只认 `.hex`）；两个无线工程通过 C51 Define
   （`WIRELESS_TX` / `WIRELESS_RX`）互相区分，切换工程后 Keil 会因编译选项
   变化而自动重新编译，不会误用上一工程的中间文件。
