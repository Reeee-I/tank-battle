# 蓝牙模式（第④接法：无线蓝牙手柄 —— 当前正式路线）

> 目录 `01_下位机程序/05_蓝牙模式/`：蓝牙手柄板固件。
> **当前定稿结论（2026-09-07）**：手头模块为 **BT05（CC2541 BLE 透传模块）**，
> 且后续大概率无法取得 HC-05/HC-06 经典蓝牙模块，因此**本方案（BT05 BLE +
> PC 端 ble_bridge 桥接 + VSPD 虚拟串口）即最终交付路线**，后续开发以此为准；
> HC-05/HC-06 经典蓝牙仅在文档中保留为"备选升级路线"（见本文件末尾与
> `03_文档/02_硬件连接/硬件连接说明.md`）。

## 一、方案概览

```
[蓝牙手柄板]                     PC（Windows 11）
 按键→UART2(EXT)                 ┌────────────────────────────────────┐
   → BT05(BLE 0xFFE0/FFE1)       │ bleak ← ble_bridge.py ← COM21      │
   ←←←←← BLE 无线 ←←←←←←←←←←←←← │   （VSPD 虚拟串口对 COM20/COM21）    │
                                 │ COM20 → 游戏 main.py --p1 COM20     │
                                 └────────────────────────────────────┘
```

- 板上行帧/下行血量帧与既有协议**完全一致**（9600 8N1，3 字节 `AA` 帧族），
  PC 游戏端**零改动**（用既有 `--p1/--p2` 显式指定 COM；自动扫描跳过蓝牙口是既有设计）。
- 蓝牙透传**全双工**：上行按键 + 下行 LED 血量条 / 命中音效均支持（游戏实测通过）。
- 为什么有 PC 端桥接：BT05 是 BLE，Windows **不会**给它生成 COM 口；
  由 `ble_bridge.py`（bleak）把 BLE 字节流接到 VSPD 虚拟串口对的一侧，
  游戏打开另一侧即可。

## 二、固件（main.c）

- 底本 = `01_有线模式/main.c`（音效版），唯一差异：通信通道用
  **串口2 EXT(TTL) 外接 BT05**，与有线版一致支持双向（上行按键包、下行血量帧）。
- `PLAYER_ID` 编译宏区分玩家：`BT_Player1.uvproj`（=1）、`BT_Player2.uvproj`（=2）；
  数码管最左位显示 1/2，LED 专用于血量条（满血3=6灯、每掉1血灭右2灯、死亡全灭）。
- 工程配置：Include = `..\common\inc;..\04_音效模块`，库 = `..\common\STC_BSP.lib`，
  音效源 = `..\04_音效模块\sound_effect.c`，Output = `..\..\HEX\`（→ `BT_Player1/2.hex`）。
  共享资源按约定只引用、不复制。

## 三、硬件接线（板 ↔ BT05）

| BT05 引脚 | 接开发板 | 说明 |
|---|---|---|
| RXD | 板 TXD2（P1.1，EXT 口） | 交叉 |
| TXD | 板 RXD2（P1.0，EXT 口） | 交叉；位置以板面丝印为准 |
| GND | 板 GND | 必须共地 |
| VCC | 板 5V（3.3V 供电版按模块说明） | BT05 为 CC2541 BLE 透传模块 |

- 板载 USB **仅供电**（充电头/充电宝，不接电脑数据）；烧录时临时用 USB，
  烧完关闭 STC-ISP。
- BT05 出厂波特率一般为 9600 8N1，与协议一致，无需 AT 配置；
  若不放心，可用 USB-TTL 以 9600 试发 `AT` 看是否回 `OK`（不同批次固件 AT 行为略有差异）。

## 四、编译 / 烧录

1. Keil 打开本目录 `BT_Player1.uvproj` / `BT_Player2.uvproj` → F7
   （Output 指向根目录 `HEX\`，产物 `BT_Player1.hex` / `BT_Player2.hex`）；
2. STC-ISP 烧录：STC15F2K60S2、**11.0592MHz**（外部晶振，与 SysClock 一致），
   烧完**关闭 STC-ISP**。

## 五、PC 端准备（一次性，首次）

1. **装 VSPD（Eltima Virtual Serial Port Driver，试用版即可）**：
   微软 WHQL 签名，Windows 10/11 可直接安装（com0com 老驱动在 Win11 25H2
   会被签名策略拒绝，勿用，详见 `03_文档/08_整理记录/整理说明.md` 蓝牙整理记录）。
2. VSPD 主界面 **Add pair** 建一对 **COM20 ⇄ COM21**（开机后自动存在）。
3. 依赖：`bleak + winrt` 由 `02_上位机程序/tools/fetch_bleak_deps.py`
   在 `tools/_bleak_deps/` 生成（本机已就绪，换机重跑即可），
   另需 `pip install pyserial`（项目 requirements 已含）。

## 六、日常使用

1. **蓝牙手柄板上电**（USB 供电，不插电脑数据）；
2. **双击项目根目录 `启动BLE桥接.bat`**：**只开一个窗口**，该窗口即桥接——
   出现 "notify 已开启" 且开始滚动 `aa 01` 数据 = 链路就绪（窗口保持运行）；
3. **双击 `启动游戏.bat`** 开游戏（等价于 `cd 02_上位机程序 && python main.py --p1 COM20`；
   若桥接尚未就绪，游戏顶部玩家1 会先显示断开，就绪后自动恢复）；
4. 若一直连不上：把蓝牙板**断电 3 秒重上电**再重开桥接（BT05 上电后才广播，
   连过一次后可能休眠，属正常脾气；必要时在 Windows 蓝牙设置里删除 BT05 配对）。

日常排障要点（依次尝试）：
- 打开 VSPD 主界面确认 **COM20 ⇄ COM21** 存在并点一次 **Apply**
  （重启电脑后常需这一步；勾选 VSPD 开机自启可减少操作）；
- 桥接窗口"扫不到模块 / 连上却没帧"→ 蓝牙板断电 3 秒重上电；
  仍不行 → **先关再开 Windows 蓝牙**（清设备缓存）→ 蓝牙板再断电重上电一次；
  还不行 → 设置→蓝牙和其他设备 **删除 BT05 配对** → 蓝牙板断电重上电；
- 双击 bat 前确认没有旧"BLE桥接"窗口在跑（bat 会自动检测 COM21 占用并提示）。

手动模式（不用 bat 时）：
```bat
:: 窗口1：桥接（保持运行）
cd 02_上位机程序\tools
python ble_bridge.py --com COM21 --addr 00:15:83:F0:15:97
:: 窗口2：游戏
cd 02_上位机程序
python main.py --p1 COM20 --p2 COM4
```

> 双蓝牙双玩家（未来扩展）：需要第二块 BT05、第二对 VSPD 端口（如 COM22/23）、
> 再开一个桥接实例（`--com COM23 --addr <模块2地址>`），玩家2 板烧 `BT_Player2.hex`。

## 七、测试与验收记录（真机实测通过）

| 项目 | 结果（2026-09-06） |
|---|---|
| 编译 | Keil C51 0 Error（BSP 库 L16 警告与既有工程一致） |
| BLE 上行 | PC 稳定收到 `AA 01 xx`，100ms/帧（8s≈80 帧） |
| 下行 LED | 满血 6 灯 / 死亡全灭，经 COM20→VSPD→桥接→BLE 直达 |
| 游戏实测 | `--p1 COM20` 蓝牙手柄完整游玩通过（用户确认） |
| 断线重连 | 断电后 0.6s 判定断开，重上电自动重连恢复 |
