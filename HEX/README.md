# HEX 统一输出目录（对照表）

> 本目录是 **本项目所有 Keil 工程的统一 HEX 输出目录**。
> 四个工程（含 MCU 有线与 无线手柄）的 Keil Output Directory 均已指向本目录
> （MCU 工程为 `..\HEX\`，无线工程为 `..\..\HEX\`），在此编译即可直接产出命名
> 统一、含义清晰的 `.hex` 文件，方便区分与上板测试。

## 文件 ↔ 板子用途对照

| HEX 文件 | 工程 | 用途 / 烧到哪块板 | 上电身份（数码管最左位 + LED） |
|---|---|---|---|
| `Wired_P1.hex` | `MCU\TankBattle_P1.uvproj`（或双 Target 的 Player1） | **有线玩家1** 手柄板（USB 直连 PC） | 数码管显示 **1**，L0 亮 |
| `Wired_P2.hex` | `MCU\TankBattle_P2.uvproj`（或双 Target 的 Player2） | **有线玩家2** 手柄板（USB 直连 PC） | 数码管显示 **2**，L7 亮 |
| `Wireless_TX_P2.hex` | `无线手柄\HEX_A_IR_Tx\HEX_A.uvproj` | **无线发送端 HEX-A**（玩家2无线手柄，红外发射，无需接 PC） | 数码管显示 **A**，L7 亮 |
| `Wireless_RX.hex` | `无线手柄\HEX_B_IR_Rx\HEX_B.uvproj` | **无线接收端 HEX-B**（红外接收 + 串口1 转发，USB 接 PC） | 数码管显示 **b**，转发时 L0 闪 |

## 数码管身份速查（一眼区分四块板）

| 显示 | 含义 |
|---|---|
| **1** | 有线玩家1 手柄板 |
| **2** | 有线玩家2 手柄板 |
| **A** | 无线发送端（HEX-A，红外发射，替代有线玩家2） |
| **b** | 无线接收端（HEX-B，红外接收后经 USB 转发给 PC） |

> 说明：无线两块板与"有线玩家2"（数码管 2）刻意使用不同字符，避免混淆。
> 'A' / 'b' 段码是在各工程 `main.c` 的 `decode_table[]` 中追加（索引 26/27），
> 属用户可自定义译码表，与 BSP 兼容。

## 本目录里的其它文件

Keil 编译时除 `.hex` 外还会在本目录生成中间文件：
`main.obj`（各工程同名，编译时互相覆盖属正常）、`*.lnp`、`*.plg`、
`*.hex` 外的无扩展名中间文件。这些都可忽略；**只有四个 `.hex` 是烧录用文件**。
如需清理，删除除 `.hex` 外的文件即可，不影响下次编译。

## 重新编译后如何取用

1. 改完某工程代码 → 在 Keil 中 F7 编译（Output 已指向本目录）；
2. 到本目录取对应 `.hex`（见上表）；
3. STC-ISP 烧录：型号 **STC15F2K60S2**，频率 **11.0592MHz**（外部晶振，与 `SysClock` 一致）；
4. 烧完务必 **关闭 STC-ISP**，否则 COM 口被占用，游戏无法打开。
