# 双人坦克对战（STC-B 学习板手柄 + PC Pygame）

使用 **STC_B 学习板（STC15F2K60S2）** 作为手柄，**PC 端 Python + Pygame** 运行
双人同屏坦克对战游戏。手柄板把按键状态每 100ms 打包上报，PC 端接收后驱动坦克
移动、转向、开火与碰撞判定。

**主推接法（485 三板手柄）**：两块手柄板经 **RS-485 总线**把按键包发给第三块
**中转板**，由中转板经一根 USB 线上报 PC——PC 端协议不变，两块玩家从同一个
COM 口按包内容自动识别绑定。

```
[手柄1板]──┐                             ┌─ UART2/485 轮询主机 ─┐
[手柄2板]──┼── RS-485 共享总线(A/B/GND)──→│  中转板(第三块板)      │── USB/串口1 ──→ PC
 每100ms采样  9600bps 8N1 半双工         │  点名P1→收→点名P2→收  │  9600bps 8N1
 被点名才应答                            └── 校验后原样转发 ──────┘  (1个COM口)
```

> 另有两种可选接法（代码/HEX 均保留，见"接线"）：旧 **USB 直连**两板手柄、
> **红外无线**手柄。PC 端三种接法通用、互不影响。

## 通信协议（板端 ↔ PC）

3 字节数据包，**9600 bps、8 数据位、1 停止位、无校验**：

| 字节 | 含义 | 取值 |
|---|---|---|
| 0 | 包头 | `0xAA`（固定） |
| 1 | 玩家号 | `0x01`（玩家1）/ `0x02`（玩家2） |
| 2 | 按键掩码 | bit0 左(左转) · bit1 右(右转) · bit2 上(前进) · bit3 下(后退) · bit4 开火(K1,单发) · bit5 重开请求(K2,单发) · bit6 K3(单发,开始界面"任意键开始"用) |

- 方向键按住时**每 100ms 持续上报**（板端以状态位方式实现）；K1 开火、K2 重开请求、
  K3 均为**按下瞬间单发一次**。
- 例：玩家1 按住"上"并按下 K1 → 发送 `AA 01 14`（0x14 = 0001_0100）。
- > **bit6=K3 为 v2.6 新增**（开始界面"任意键开始"用，对战中 PC 忽略）。有线手柄需
  > 重新烧录 `HEX\USB_Player1.hex` / `HEX\USB_Player2.hex`；无线手柄需重烧
  > `HEX\IR_Player2.hex`（三块 HEX 已重编 0 Error）。

### PC → 板 下行帧（手柄 LED 血量联动，v2.8 新增）

仍是 3 字节、同波特率（命令码与玩家号 01/02、点名码 E1/E2 永不冲突）：

| 字节 | 含义 | 取值 |
|---|---|---|
| 0 | 包头 | `0xAA`（固定） |
| 1 | 下行命令码 | `0xD1`（玩家1 血量）/ `0xD2`（玩家2 血量） |
| 2 | 血量 | `0`~`3`（3 = 满血） |

- **LED 血条语义**（只作用于两块玩家手柄板，中转/接收板不显示血量）：
  满血(3) = **L0~L5 六灯全亮**；每掉 1 血灭**右侧 2 灯**（3→6 灯、2→4 灯、1→2 灯）；
  死亡(0) = **全灭**。身份显示由**数码管最左位 1/2** 承担（LED 不再亮身份灯）；
  上电到 PC 首次下发血量之间 LED 默认全灭。
- **发送时机**：开局（满血 3）、每次命中扣血、血包回血、死亡归零、K2/鼠标重开复位。
  板子中途重插/重连会自动补发一次当前血量。
- **发送路径**：① 旧 USB 直连 = PC 写各玩家绑定 COM；② 485 = PC 写**中转板** COM
  （单 COM 内含 D1/D2 两帧），中转板在总线空闲窗口转发给对应手柄（板间字节原样）；
  ③ 红外无线方案本期**不支持**（HEX-A 无线手柄无下行通道，LED 保持全灭）。

## 一、PC 端运行

### 环境要求
- Windows 10/11，Python 3.8+
- 安装依赖：`pip install -r PC/requirements.txt`（pygame、pyserial）

### 运行
```bat
cd PC
python main.py                    :: 自动扫描串口并绑定
python main.py --p1 COM3 --p2 COM5 :: 手动指定两个手柄的串口
python main.py --no-keyboard      :: 纯手柄模式（默认开启键盘调试控制）
python main.py --debug            :: 打印按键/重开诊断（排查重开问题时用）
```

### 操作说明
| 动作 | 板子（手柄） | 键盘（调试/备用） |
|---|---|---|
| 开始（程序启动后） | **任一手柄任意键** | 任意键 / 鼠标点击 |
| 前进/后退 | 导航键 上/下（按住持续） | 玩家1 W/S；玩家2 ↑/↓ |
| 左转/右转 | 导航键 左/右（按住持续） | 玩家1 A/D；玩家2 ←/→ |
| 开火 | K1（按下瞬间） | 玩家1 空格；玩家2 回车 |
| 重开（对局结束后） | **任一手柄按 K2**（或 PC 端**鼠标点击**） | 鼠标点击 |
| 退出 | — | Esc |

> 程序启动先显示**开始界面**（标题/操作说明/道具简介），按任意键、点击鼠标或任一手柄
> 任意键进入对战；**对局结束后 K2/鼠标点击重开直接开下一局，不再经过开始界面**。
> 键盘控制默认开启，两块板子未接入时也可直接双人对战调试。
> **对局结束后重开：点击鼠标 或 任一手柄按 K2**（R/回车/K1 不用于重开——用户需求）。

### 游戏规则速览（与代码常量一致）
| 项目 | 值 | 备注 |
|---|---|---|
| 战场 | 800×600 | 灰色障碍挡坦克/子弹；**每局开局随机抽 1 张地图**（共 6 张，画面左下角显示地图名） |
| 坦克 | 30×30，3 条命 | 移动 3px/帧；转向 2°/帧(约120°/s)；**坦克间不可互相穿过** |
| 子弹 | 半径 5，速度 5px/帧 | 同屏每车最多 3 发；冷却 200ms；K1/空格为按下瞬间单发 |
| 命中 | 对方 -1 命、自己 +10 分 | 被击中回出生点并无敌 1s（重生无敌/道具护盾吸收子弹不掉血） |
| 道具 | 4 种随机刷出，碾过即拾取 | 加速 6s(×1.5速) / 炮弹增强 6s(命中 -2 血) / 血包(+1命,上限3) / 护盾 8s或挡1发；HUD 增益栏显示剩余秒数 |
| 胜负 | 一方生命归零 | 结算瞬间其余子弹清场（不会出现击杀后再被反杀/幽灵弹） |

**道具与平衡设计**（数值/节奏集中在 `game.py` 道具常量区，可一键调平衡）：
- **中频少量**：开局 6s 出第一件，之后每 10~15s 随机刷 1 件、四种等概率，场上同时
  最多 2 件——道具给对局加变数，但不喧宾夺主（v2.5 起较初版频率约降 1/4）；
- **位置公平且可达**：刷在"整辆坦克能停靠"的空地（避开障碍/坦克/其他道具），
  坦克**碾过即拾取**；每件 10s 无人拾取自动消失（临消失 3s 闪烁提示），不堆积不遗留；
- **防滚雪球**：① 被击中重生时**清空全部增益与护盾**（被打回去就是代价）；
  ② 血包 +1 命且上限 3，满血拾取无效并消耗——对领先方是负收益，天然把血包留给
  落后方，形成反滚雪球资源；③ 炮弹增强虽单发 -2 血，但只持续 6s 且伤害在**开火瞬间
  快照**（增强弹带白色大光环，对手可识别），有明确爆发窗口可被护盾/走位反制；
  ④ 护盾挡下一发**立即失效**、且 8s 不到也会过期——不能长期龟缩免疫；
- **不叠加**：同类增益重复拾取不叠加，仅刷新为满时长。
- **反馈醒目**：HUD 增益栏秒数**实时倒数**（6s→5s→…→1s），归零瞬间该增益恰好失效
  （显示与效果同一时钟、严格同步）；拾取血包时坦克头顶上浮"**生命 +1**"（绿）/满血时
  "生命已满"（灰）提示，1.2s 渐隐，回血过程一目了然。

**地图平衡设计**：6 张地图（经典战场/十字要塞/中央堡垒/回廊/街巷/石柱阵）全部
关于战场中线左右**镜像对称**（两玩家地形完全公平），且中央都设置了掩体——两出生点
(150,300)/(650,300) 正前方的直线弹道被遮挡，**刚开局双方无法隔空直射**，必须先移动
走位绕开掩体再交火（修复旧版"开局即对射"的不平衡）。地图约束由
`tests/test_maps.py` 自动校验（对称/出生留空/开局直线遮挡/全图连通）。

### 串口自动识别与断线处理
- 玩家身份由**数据包内容**决定：哪个 COM 口先收到玩家 X 的合法包，即绑定为玩家 X，
  线序插反也不影响；**485 中转板方案下两块玩家从同一个 COM 口交替上报，同样按
  包内容各自自动绑定**（单口双玩家，游戏无需任何修改）；
- 某玩家超过 0.6s 未上报 → 界面顶部显示"断开!"并冻结其输入（不清生命、不判负），
  每 2s 自动尝试重连，重插 USB/恢复 485 连接后自动恢复；
- 串口被占用（如 STC-ISP 未关闭）时会给出明确提示；画面顶部每个玩家有
  **绿点=在线 / 橙点=断开 / 灰点=未绑定** 状态。
  > 提示：485 方案建议先用 `python tools/serial_probe.py` 确认中转板 COM 上两玩家
  > 交替出包（~10Hz 各一包），再开游戏。

## 二、开发板端（板端固件总览）

板端固件分三族，PC 端通用：

| 方案 | 固件/工程 | HEX | 说明 |
|---|---|---|---|
| **① 485 三板手柄（主推）** | `485手柄\`（main_handle.c ×2 工程 + main_hub.c） | `485_Player1.hex` / `485_Player2.hex` / `485_Relay.hex` | 两块手柄走 485 总线，第三块中转板 USB 转发 PC（单 COM）；详见 `485手柄\README.md` |
| ② 旧 USB 直连（可选） | 本目录 `MCU\`（main.c） | `USB_Player1.hex` / `USB_Player2.hex` | 两块手柄各自 USB 直连 PC（两个 COM）；见下文 |
| ③ 红外无线（可选） | `无线手柄\` | `IR_Player2.hex` / `IR_Relay.hex` | 玩家2 无线手柄 + 接收转发板；见 `无线手柄\` 各 README |

> `main.c` 顶部两个宏按需理解：
> - `PLAYER_ID`：1 → 玩家1；2 → 玩家2。**身份显示 = 数码管最左位数字 1/2 + 协议玩家号**
>   （v2.8 起 LED 不再亮身份灯，专用于血量血条）；**LED(L0~L5) = 所控坦克血量**：

### 接线（三种方案，485 为当前主推）
| 方案 | 连线 | 说明 |
|---|---|---|
| **① 485 三板（主推）** | 两块手柄板 485 接口 A/A、B/B、GND 并成一条总线接中转板；中转板 USB 接 PC；手柄板 USB 仅供电 | 一根 USB 即一个 COM；中转板每 100ms 点名两手柄并原样转发 PC；接线/供电/终端电阻详见 `485手柄\README.md` |
| **② 旧 USB 直连（可选）** 板载 USB | 每块板一根 USB 线直连电脑（板载 CH340 → 串口1，P3.0/P3.1） | 两根 USB 线即得两个 COM 口，最简（旧方案） |

> 方案 ③ 使用板载 USB 的同时外接 USB-TTL 仅作串口监听时，请保证两者共地、不要从两路同时给板子供电。

## 四、常见问题（FAQ）

**Q1：找不到串口 / 游戏提示"未发现可用串口"**
检查 USB 是否插好、驱动（CH340 等）是否安装；关闭占用该端口的软件（尤其 STC-ISP）。

**Q2：能打开端口但坦克不动**
先跑 `tools/serial_probe.py` 看是否有 `玩家1/玩家2` 的包：无包 → 查板子是否烧录成功、
数码管是否显示 1/2、波特率是否 9600；有包但游戏不动 → 确认游戏窗口处于活动状态、
按键掩码方向语义是否正确（板子上=前进）。

**Q3：玩家身份反了/错乱**
自动绑定以第一个收到的合法包为准：先上电的那块板就是对应玩家。也可 `--p1/--p2` 手动指定。

**Q4：开枪没反应**
K1 为"按下瞬间单发"，需要一下一下按；按住不放不会连发（与板端协议一致）。
同屏最多 3 发、冷却 200ms，注意节奏。

**Q5：界面上中文变成方块**
系统缺少微软雅黑/黑体等中文字体（极少数精简系统），请安装任意中文字体后重试；
游戏红心等图标为自绘，不依赖 emoji 字体。

**Q6：编译报错**
先核对 Keil 工程 Include 路径、`STC_BSP.lib` 是否在工程内、芯片型号与 Target 配置；
若用的是自己拷来的 V3.6b `STC_BSP.lib`，确认与 `inc/` 头文件为同一版本。

**Q7：改了波特率/频率**
PC 端 `serial_handler.py` 的 `BAUDRATE`、板端 `main.c` 的 `Uart1Init/Uart2Init` 与
`SysClock`（下载频率）需三者一致。

**Q8：对局结束如何重开？（原 R 键方案已按需求移除）**
重开方式只有两种（结算画面有提示）：**点击鼠标任意处** 或 **任一手柄按 K2**。
K2 走板子串口信号（协议 bit5），不经过键盘/输入法，最可靠；鼠标点击与键盘事件同链路，
Esc 能退出则点击一定能用。若两者都无反应：运行 `python main.py --debug` 复现一次，
程序会把收到的按键与"重开"触发打印在控制台并**追加写入 `PC\debug_keys.log`**
（双击启动看不到控制台时看这个文件）——把其中相关行发回即可精确定位。

**Q9：找不到 USB_Player2.hex / 不知怎么编译玩家2**
工程里有两个 Target，Keil 默认只编译当前选中的那一个（默认 Player1）。
三选一即可：① Target 下拉框切到 **Player2** 再按 F7；② Project→Batch Build 一次编两个；
③ 直接打开新增的便捷工程 `MCU\TankBattle_P2.uvproj` 编译。产物统一在根目录 `HEX\`：
`USB_Player1.hex`（Player1）与 `USB_Player2.hex`（Player2）。
（485 方案的三个 HEX 各有独立工程 `485手柄\RS485_*.uvproj`，单 Target，F7 即出。）

**Q10：485 三板方案接好了但游戏没反应 / 只显示一个玩家**
① 先看三块板数码管：手柄应为 **1/2**、中转板应为 **C**（L0 在转发时点亮）；
② `python PC\tools\serial_probe.py` 看中转板 COM 是否交替出现 玩家1/玩家2 的包
（~10Hz 各一包）；无包 → 查 A/B 是否接反、是否共地、波特率 9600、STC-ISP 是否关闭；
只有一方的包 → 查对应手柄板供电与 485 接线（游戏里该玩家会变橙"断开!"）。

**Q11：手柄 LED 血条不动 / 全灭 / 亮灯数与血量不符**
① 确认三族固件是 v2.8 新 HEX（USB_Player1 / USB_Player2、485_Player1 / 485_Player2 均已支持下行血量）；
② 确认接法有下行通道：USB 直连两板 / 485 中转板都可以，**红外无线（玩家2 无线手柄）
本期不支持** → 无线手柄 LED 保持全灭属正常；
③ 身份看数码管 1/2，LED 只在"开局后才按血量亮"——开始界面、未进对局时全灭属正常；
④ 血条只反映**本板所控角色**的血量：血包回血会补亮、被打会灭灯、死亡全灭；
⑤ 板子中途重插会自动补发一次当前血量；若仍不对，先跑 `python main.py --debug` +
`tools/serial_probe.py` 确认下行帧（`AA D1/D2 HP`）已发出。
