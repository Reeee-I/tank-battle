# 双人坦克对战（STC-B 学习板手柄 + PC Pygame）

使用 **两块 STC_B 学习板（STC15F2K60S2）** 作为游戏手柄，**PC 端 Python + Pygame** 运行
双人同屏坦克对战游戏。板子通过串口每 100ms 上报一次按键状态，PC 端接收后驱动坦克
移动、转向、开火与碰撞判定。

```
[STC-B 板1](玩家1, 亮L0) ──┐                    ┌─ 接收线程 ─┐
[STC-B 板2](玩家2, 亮L7) ──┼─ UART 9600 8N1 ──→│ 协议解析/自动绑定 ├─→ 游戏主循环 60FPS
      每100ms发3字节包      └─ 两个 COM 口 ──→  └─ 断线检测/重连 ─┘      └→ 渲染/碰撞/胜负
```

## 通信协议（板端 ↔ PC）

3 字节数据包，**9600 bps、8 数据位、1 停止位、无校验**：

| 字节 | 含义 | 取值 |
|---|---|---|
| 0 | 包头 | `0xAA`（固定） |
| 1 | 玩家号 | `0x01`（玩家1）/ `0x02`（玩家2） |
| 2 | 按键掩码 | bit0 左(左转) · bit1 右(右转) · bit2 上(前进) · bit3 下(后退) · bit4 开火(K1,单发) · bit5 重开请求(K2,单发) · bit6 K3(单发,开始界面"任意键开始"用) |

- 方向键按住时**每 100ms 持续上报**（板端以状态位方式实现）；K1 开火、K2 重开请求、
  K3 均为**按下瞬间单发一次**。
- 例：玩家1 按住"上"并按下 K1 → 发送 `AA 01 14`（0x14 = 0001_0100）。
- > **bit6=K3 为 v2.6 新增**（开始界面"任意键开始"用，对战中 PC 忽略）。有线手柄需
  > 重新烧录 `HEX\Wired_P1.hex` / `HEX\Wired_P2.hex`；无线手柄需重烧
  > `HEX\Wireless_TX_P2.hex`（三块 HEX 已重编 0 Error）。

## 一、PC 端运行

### 环境要求
- Windows 10/11，Python 3.8+
- 安装依赖：`pip install -r PC/requirements.txt`（pygame、pyserial）

### 运行
```bat
cd PC
python main.py                    :: 自动扫描串口并绑定
python main.py --p1 COM3 --p2 COM5 :: 手动指定两个手柄的串口
python main.py --no-keyboard      :: 纯手柄模式（默认开启键盘调试控制）
python main.py --debug            :: 打印按键/重开诊断（排查重开问题时用）
```

### 操作说明
| 动作 | 板子（手柄） | 键盘（调试/备用） |
|---|---|---|
| 开始（程序启动后） | **任一手柄任意键** | 任意键 / 鼠标点击 |
| 前进/后退 | 导航键 上/下（按住持续） | 玩家1 W/S；玩家2 ↑/↓ |
| 左转/右转 | 导航键 左/右（按住持续） | 玩家1 A/D；玩家2 ←/→ |
| 开火 | K1（按下瞬间） | 玩家1 空格；玩家2 回车 |
| 重开（对局结束后） | **任一手柄按 K2**（或 PC 端**鼠标点击**） | 鼠标点击 |
| 退出 | — | Esc |

> 程序启动先显示**开始界面**（标题/操作说明/道具简介），按任意键、点击鼠标或任一手柄
> 任意键进入对战；**对局结束后 K2/鼠标点击重开直接开下一局，不再经过开始界面**。
> 键盘控制默认开启，两块板子未接入时也可直接双人对战调试。
> **对局结束后重开：点击鼠标 或 任一手柄按 K2**（R/回车/K1 不用于重开——用户需求）。

### 游戏规则速览（与代码常量一致）
| 项目 | 值 | 备注 |
|---|---|---|
| 战场 | 800×600 | 灰色障碍挡坦克/子弹；**每局开局随机抽 1 张地图**（共 6 张，画面左下角显示地图名） |
| 坦克 | 30×30，3 条命 | 移动 3px/帧；转向 2°/帧(约120°/s)；**坦克间不可互相穿过** |
| 子弹 | 半径 5，速度 5px/帧 | 同屏每车最多 3 发；冷却 200ms；K1/空格为按下瞬间单发 |
| 命中 | 对方 -1 命、自己 +10 分 | 被击中回出生点并无敌 1s（重生无敌/道具护盾吸收子弹不掉血） |
| 道具 | 4 种随机刷出，碾过即拾取 | 加速 6s(×1.5速) / 炮弹增强 6s(命中 -2 血) / 血包(+1命,上限3) / 护盾 8s或挡1发；HUD 增益栏显示剩余秒数 |
| 胜负 | 一方生命归零 | 结算瞬间其余子弹清场（不会出现击杀后再被反杀/幽灵弹） |

**道具与平衡设计**（数值/节奏集中在 `game.py` 道具常量区，可一键调平衡）：
- **中频少量**：开局 6s 出第一件，之后每 10~15s 随机刷 1 件、四种等概率，场上同时
  最多 2 件——道具给对局加变数，但不喧宾夺主（v2.5 起较初版频率约降 1/4）；
- **位置公平且可达**：刷在"整辆坦克能停靠"的空地（避开障碍/坦克/其他道具），
  坦克**碾过即拾取**；每件 10s 无人拾取自动消失（临消失 3s 闪烁提示），不堆积不遗留；
- **防滚雪球**：① 被击中重生时**清空全部增益与护盾**（被打回去就是代价）；
  ② 血包 +1 命且上限 3，满血拾取无效并消耗——对领先方是负收益，天然把血包留给
  落后方，形成反滚雪球资源；③ 炮弹增强虽单发 -2 血，但只持续 6s 且伤害在**开火瞬间
  快照**（增强弹带白色大光环，对手可识别），有明确爆发窗口可被护盾/走位反制；
  ④ 护盾挡下一发**立即失效**、且 8s 不到也会过期——不能长期龟缩免疫；
- **不叠加**：同类增益重复拾取不叠加，仅刷新为满时长。
- **反馈醒目**：HUD 增益栏秒数**实时倒数**（6s→5s→…→1s），归零瞬间该增益恰好失效
  （显示与效果同一时钟、严格同步）；拾取血包时坦克头顶上浮"**生命 +1**"（绿）/满血时
  "生命已满"（灰）提示，1.2s 渐隐，回血过程一目了然。

**地图平衡设计**：6 张地图（经典战场/十字要塞/中央堡垒/回廊/街巷/石柱阵）全部
关于战场中线左右**镜像对称**（两玩家地形完全公平），且中央都设置了掩体——两出生点
(150,300)/(650,300) 正前方的直线弹道被遮挡，**刚开局双方无法隔空直射**，必须先移动
走位绕开掩体再交火（修复旧版"开局即对射"的不平衡）。地图约束由
`tests/test_maps.py` 自动校验（对称/出生留空/开局直线遮挡/全图连通）。

### 串口自动识别与断线处理
- 玩家身份由**数据包内容**决定：哪个 COM 口先收到玩家 X 的合法包，即绑定为玩家 X，
  两块板子线序插反也不影响；
- 某玩家超过 0.6s 未上报 → 界面顶部显示"断开!"并冻结其输入（不清生命、不判负），
  每 2s 自动尝试重连，重插 USB 后自动恢复；
- 串口被占用（如 STC-ISP 未关闭）时会给出明确提示；画面顶部每个玩家有
  **绿点=在线 / 橙点=断开 / 灰点=未绑定** 状态。

## 二、开发板端（MCU）

### 板端文件清单（均已就位）
| 文件 | 说明 |
|---|---|
| `MCU/main.c` | 唯一源文件。编译宏 `PLAYER_ID=1` 亮 L0、数码管显示 1、发 0x01（玩家1）；`=2` 亮 L7、数码管显示 2、发 0x02（玩家2） |
| `MCU/STC_BSP.lib` | BSP 库（当前为与工程配套的可编译副本；若你持有 V3.6b 的 `STC_BSP.lib`，同名替换即可） |
| `MCU/inc/` | BSP 头文件目录（工程 Include 路径指到这里） |
| `MCU/TankBattle.uvproj` | Keil 工程（双 Target），另有 `TankBattle_P1.uvproj` / `TankBattle_P2.uvproj` 单 Target 便捷工程 |

> `main.c` 顶部两个宏按需理解：
> - `PLAYER_ID`：1 → 玩家1；2 → 玩家2。**身份显示 = LED(L0/L7) + 数码管最左位数字 1/2 + 协议玩家号**；
> - `UART_IF`：**0 = 板载 USB 串口1（默认，USB 线直连电脑）**；1 = EXT 扩展口 UART2（备选）。
>
> `SysClock` 在 main.c 中定义为 11059200（11.0592MHz），必须与 **STC-ISP 下载时选择的频率一致**。

### 方式 A：直接打开参考工程（推荐）
1. 确保 Keil 中已通过 **STC-ISP 的"Keil仿真设置"**安装 STC 设备库（老工程已验证可用）；
2. 双击打开 `MCU\TankBattle.uvproj`（双 Target 工程）；
3. 编译 **Wired_P1.hex**：工具栏 Target 下拉框选 **Player1** → 编译（F7）→ `HEX\Wired_P1.hex`；
4. 编译 **Wired_P2.hex**（三选一）：
   - ① 同一双 Target 工程：把 Target 下拉框切换为 **Player2** → 再按 F7 → `HEX\Wired_P2.hex`；
   - ② 菜单 Project → Batch Build → 勾选两个 Target → Rebuild，一次生成两个 HEX；
   - ③ 直接打开便捷工程 `MCU\TankBattle_P2.uvproj`（单 Target=Player2）→ F7 → `HEX\Wired_P2.hex`。
5. 若导入后个别设置被 Keil 重置，按下方"方式 B"的清单核对一遍即可。

### 方式 B：手动新建工程（逐条核对配置）
1. **新建工程**（Project → New uVision Project），芯片选择 **STC15F2K60S2**；
2. **添加文件**：`main.c`；添加库文件 `STC_BSP.lib`（Add Existing Files 时文件类型选 *）；
3. **Include Paths**（C51 选项卡 → Include Paths）：指向 `MCU\inc`；
4. **内存模式 Memory Model = Small**；**代码优化 Optimize = Level 8**；
5. **Output 选项卡勾选 "Create HEX File"**，Output Directory 指向 `..\HEX\`，Output Name 建议 `Wired_P1`；
6. 玩家区分二选一：
   - 双 Target：复制工程 Target 为 Player1/Player2，各自在 C51 选项卡
     Define 中写 `PLAYER_ID=1` / `PLAYER_ID=2`，Output Name 分别 `Wired_P1`/`Wired_P2`；
   - 或直接改 `main.c` 顶部 `#define PLAYER_ID 1`，编两次（第二次改 2）。
7. 编译通过（无 Error）后，在 `HEX\`（统一输出目录）得到 HEX。

### 烧录（STC-ISP）
1. 板1 插 USB，打开 STC-ISP，选择单片机型号 **STC15F2K60S2**；
2. 频率按你的板子选择（外部晶振 11.0592MHz → 与 `SysClock` 一致）；
3. 载入 `HEX\Wired_P1.hex` → 点"下载/编程"（必要时按提示给板上电）；
4. 完成后再对板2 载入 `HEX\Wired_P2.hex` 烧录；
5. **验证身份**：板1 上电后 L0 常亮、数码管最左位显示 **1**；板2 上电后 L7 常亮、数码管最左位显示 **2** —— 分别对应玩家1/玩家2；
6. 烧录后 **关闭 STC-ISP**（否则 COM 口被占用，游戏打不开）。

> 无线手柄（红外）两块板的 HEX 为 `HEX\Wireless_TX_P2.hex`（发送端，数码管 'A'）与
> `HEX\Wireless_RX.hex`（接收端，数码管 'b'），详见 `无线手柄\` 目录各 README。

> 若修改过 `main.c`（如身份显示、协议等），需**重新编译两个 Target** 并分别烧录。

### 接线（两种方案）
| 方案 | 连线 | 说明 |
|---|---|---|
| **A（主，默认代码）** 板载 USB | 每块板一根 USB 线直连电脑（板载 CH340 → 串口1，P3.0/P3.1） | 两根 USB 线即得两个 COM 口，最简 |
| **B（备）** EXT 口 UART2 | 每板：EXT 口 **P1.1(TXD2) → USB-TTL 模块 RX**，**GND 共地**（P1.0/RX 可不接，纯上行） | 需 2 个 CH340 模块；板子供电仍走板载 USB；代码把 `UART_IF` 改为 1 重新编译 |

> 方案 B 使用板载 USB 的同时外接 USB-TTL 仅作串口监听时，请保证两者共地、不要从两路同时给板子供电。

| 5 | 胜负 | 任一方生命归零 → 中央显示"玩家X 获胜！" | ☑ |
| 6 | 障碍物 | 坦克无法穿过灰色障碍；子弹碰到障碍消失 | ☑ |
| 7 | 重开 | 对局结束后**点击鼠标** 或 **任一手柄按 K2** → 恢复初始状态重新开始 | ☑ |
| 附 | 断线提示 | 拔掉某板 USB → 对应状态变橙"断开!"；插回后自动恢复 | ☑ |

## 四、常见问题（FAQ）

**Q1：找不到串口 / 游戏提示"未发现可用串口"**
检查 USB 是否插好、驱动（CH340 等）是否安装；关闭占用该端口的软件（尤其 STC-ISP）。

**Q2：能打开端口但坦克不动**
先跑 `tools/serial_probe.py` 看是否有 `玩家1/玩家2` 的包：无包 → 查板子是否烧录成功、
L0/L7 是否点亮、波特率是否 9600；有包但游戏不动 → 确认游戏窗口处于活动状态、
按键掩码方向语义是否正确（板子上=前进）。

**Q3：玩家身份反了/错乱**
自动绑定以第一个收到的合法包为准：先上电的那块板就是对应玩家。也可 `--p1/--p2` 手动指定。

**Q4：开枪没反应**
K1 为"按下瞬间单发"，需要一下一下按；按住不放不会连发（与板端协议一致）。
同屏最多 3 发、冷却 200ms，注意节奏。

**Q5：界面上中文变成方块**
系统缺少微软雅黑/黑体等中文字体（极少数精简系统），请安装任意中文字体后重试；
游戏红心等图标为自绘，不依赖 emoji 字体。

**Q6：编译报错**
先核对 Keil 工程 Include 路径、`STC_BSP.lib` 是否在工程内、芯片型号与 Target 配置；
若用的是自己拷来的 V3.6b `STC_BSP.lib`，确认与 `inc/` 头文件为同一版本。

**Q7：改了波特率/频率**
PC 端 `serial_handler.py` 的 `BAUDRATE`、板端 `main.c` 的 `Uart1Init/Uart2Init` 与
`SysClock`（下载频率）需三者一致。

**Q8：对局结束如何重开？（原 R 键方案已按需求移除）**
重开方式只有两种（结算画面有提示）：**点击鼠标任意处** 或 **任一手柄按 K2**。
K2 走板子串口信号（协议 bit5），不经过键盘/输入法，最可靠；鼠标点击与键盘事件同链路，
Esc 能退出则点击一定能用。若两者都无反应：运行 `python main.py --debug` 复现一次，
程序会把收到的按键与"重开"触发打印在控制台并**追加写入 `PC\debug_keys.log`**
（双击启动看不到控制台时看这个文件）——把其中相关行发回即可精确定位。

**Q9：找不到 Wired_P2.hex / 不知怎么编译玩家2**
工程里有两个 Target，Keil 默认只编译当前选中的那一个（默认 Player1）。
三选一即可：① Target 下拉框切到 **Player2** 再按 F7；② Project→Batch Build 一次编两个；
③ 直接打开新增的便捷工程 `MCU\TankBattle_P2.uvproj` 编译。产物统一在根目录 `HEX\`：
`Wired_P1.hex`（Player1）与 `Wired_P2.hex`（Player2）。
