## 2. 音效模块设计（sound_effect.h / sound_effect.c）

### 2.1 对外 API（宏关闭时全部为空操作）

| 函数 | 作用 | 调用位置 |
| :--- | :--- | :--- |
| `void Sound_Init(void)` | 模块初始化（内部调用一次 BSP `BeepInit()`） | main() 中、`MySTC_Init()` 之前 |
| `void Sound_Play(unsigned char sound_id)` | 请求播放一个音效（带优先级裁决） | 按键按下瞬间 / 血量下行帧等事件处 |
| `unsigned char Sound_IsBusy(void)` | 1=忙（正在响 / 等接播 / 音步间隔），0=空闲 | main 的 100ms 移动音轮询处 |
| `void Sound_Tick(void)` | 10ms 状态机驱动 | main 注册的 10ms 回调中调用 |

### 2.2 编译开关（均可在 Keil 工程 C51 的 Define 中覆盖）

```c
#define SOUND_ENABLED          1   /* 0=禁用（全部函数空操作）1=启用 */
#define SOUND_VOLUME           3   /* 音量档 1~10（对应串联合适的限流电阻，见第 3 节） */
#define SOUND_PRIORITY_ENABLE  1   /* 1=启用优先级抢占 0=忙则丢弃新音 */
```

### 2.3 音效定义（所有玩家手边板子一致）

| 游戏事件 | ID | 频率 | 时长 | 优先级 | 听感 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 开火 | `SOUND_FIRE` | 1500 Hz | 50 ms | 高(3) | 短促"哒" |
| 移动 | `SOUND_MOVE` | 800 Hz | 20 ms | 低(1) | 方向键按住时每 100ms 一声"嗒" |
| 被击中 | `SOUND_DAMAGE` | 500 Hz | 200 ms | 中(2) | 低沉"呜" |
| 击中敌人 | `SOUND_HIT` | 1200 Hz | 80ms×2（双短促） | 中(2) | "哒哒"两连 |
| 游戏结束 | `SOUND_GAMEOVER` | 1500→500 Hz | 各 100 ms | 高(3) | 下扫"哔—嗡" |

* `SOUND_HIT` 已内置但默认不触发：目前 PC 下行只含"本车血量"，无法判断"本车击中敌人"；
  待 PC 端协议扩展出命中指令后，直接在收到处调用 `Sound_Play(SOUND_HIT)` 即可（见第 8 节）。

### 2.4 状态机 / 优先级 / 序列

- 时间基准：`Sound_Tick()` 每 10ms 调用一次（由 main 注册的 10ms 系统事件回调驱动）。
- 同一时刻只播放一个音效，音效按"音步序列"推进：
  单音（FIRE/MOVE/DAMAGE）1 步；双短促/下扫（HIT/GAMEOVER）2 步，步间自动插入 10ms 静音。
- 优先级裁决（`SOUND_PRIORITY_ENABLE=1`）：
  - 新音优先级 ≥ 当前音 → **抢占**：丢弃当前音剩余音步，蜂鸣器空闲瞬间立刻接播新音；
  - 新音优先级 < 当前音 → 丢弃本次请求（不排队、不堆积）。
- 特殊边界已处理：
  - 非法 ID 忽略；首帧血量只建基线不发声；回血/重发同血量不发声（只认"下降沿"）；
  - 发声看门狗：超过"设定时长+100ms"仍 busy 则自动复位，模块永不卡死；
  - 移动音在忙时由优先级裁决丢弃，主程序还先用 `Sound_IsBusy()` 过滤，避免无效请求。

### 2.5 重要限制（为什么"打断"是接续而非硬截停）

BSP Ver3.6b 只提供 `SetBeep(freq,time)` / `GetBeepStatus()`：
- 蜂鸣器正在发声期间再次调用 `SetBeep` 会返回 `enumSetBeepFail`（没有 StopBeep）；
- 约束又要求不得直接操作寄存器。因此**正在响的那一个单音无法 API 截停**，
  只能等它按设定时长自然响完，随后立刻接播抢占的新音。
- 由于所有音效都短促（20~200ms），实测听感为"极短延迟接续"，完全满足对战节奏。

## 3. 音量控制（重要：先读再动手）

### 3.1 为什么音量用"硬件串联电阻"方案

`SetBeep(freq,time)` 只能设频率与时长：BSP 内部 PWM 占空比固定（50%），
库未开放占空比/幅度接口，约束又不允许直接写 PWM/CCP 寄存器，
所以**软件调占空比这条路在 Ver3.6b 上不可行**（若将来库开放占空比参数，
可在音效模块内加一行映射，其余代码不变）。

采用任务书中"方案 a + 方案 c"的组合：**在蜂鸣器驱动输出回路串联限流电阻**，
并统一封装成 `Sound_Play()` 接口（模块内部也只有这一个发声入口）。

### 3.2 做法与档位参考

在蜂鸣器（BZ）驱动端到蜂鸣器之间串入电阻（从板上蜂鸣器供电跳线/插针处断开串接，
或用飞线串在蜂鸣器正极回路；阻值不关键，从大往小试）：

| SOUND_VOLUME | 建议串联电阻 | 听感目标 |
| :--- | :--- | :--- |
| 1 ~ 2 | 1 kΩ 左右 | 很近的桌面对战，非常柔和 |
| **3 ~ 5（默认 3）** | **470Ω ~ 680Ω** | **20~30cm 清晰可听、不刺耳（推荐起步值）** |
| 6 ~ 10 | 100Ω ~ 220Ω 或直连 | 需要更大声的演示场合 |

调试顺序：先用 1kΩ 试听，偏轻再逐档换小（680 → 510 → 330 → 220 → 100Ω），
直到 20cm 距离"清晰、不发刺"为止。**默认 SOUND_VOLUME=3 对应约 510Ω~1kΩ 起步。**

> 若你的板子蜂鸣器旁已有 0Ω 跳线/短路帽，可直接替换为电阻；没有的话用杜邦线飞线串联即可，
> 不焊接也不影响验证。

## 4. 集成步骤（逐工程，推荐顺序）

> 通则：所有工程都要 **先备份原 main.c**；改动只用"改名覆盖 + 添加文件"，不删任何原文件。

### 4.1 有线手柄板 ×2（工程：MCU 或 MCU\TankBattle_P1/P2，烧 USB_Player1/2）

1. 备份 `MCU\main.c`；
2. 把 `sound\main_wired_handle_sound.c` 改名 `main.c` 复制到 `MCU\`；
3. 把 `sound\sound_effect.h`、`sound\sound_effect.c` 复制到 `MCU\`；
4. Keil 中打开工程 → 右键 "Source Group 1" → *Add Existing Files…* 加入 `sound_effect.c`；
5. 确认 C51 选项 Include Path 含 `.\inc`（本来就含，`Beep.h` 在其中）；
6. 编译宏照旧：Target Player1 的 Define `PLAYER_ID=1`、Player2 的 `PLAYER_ID=2`；
   `SOUND_ENABLED` 默认 1，不必写；
7. 编译：0 Error（警告仅剩 BSP 库内未调用段 L16，见第 9 节 FAQ）；
8. 用 STC-ISP 分别烧录两块板（频率 11.0592MHz），数码管显示 1 / 2。

### 4.2 无线发送端 HEX-A（工程：无线手柄\HEX_A_IR_Tx，烧 IR_Player2.hex）

1. 备份 `无线手柄\HEX_A_IR_Tx\main.c`；
2. 把 `sound\main_wireless_tx_sound.c` 改名 `main.c` 复制进去；
3. 把 `sound_effect.h`、`sound_effect.c` 复制进去，并在工程中加入 `sound_effect.c`；
4. **注意：无线工程 inc 目录自包含、没有 `Beep.h`**——
   把 `MCU\inc\Beep.h` 复制到 `无线手柄\HEX_A_IR_Tx\inc\`（或给工程 Include Path 追加 `..\..\MCU\inc`）；
5. 编译 → 烧录（数码管 'A'）。

### 4.3 无线接收端 HEX-B（工程：无线手柄\HEX_B_IR_Rx，烧 IR_Relay.hex）—— 不发声

1. 备份原 `main.c`；
2. 把 `sound\main_wireless_rx_disabled.c` 改名 `main.c` 复制进去；
3. 把 `sound_effect.h`（仅头文件）复制到同目录，消除 include 提示；
   **不要**把 `sound_effect.c` 加入工程；
4. 编译 → 烧录（数码管 'b'）。本板与未加音效功能时完全一致，无任何发声行为。

### 4.4 （可选）485 手柄板 ×2（工程：485手柄\RS485_Handle1/2，烧 485_Player1/2）

与 4.1 完全相同，只是源文件是 `main_485_handle_sound.c`（两块板共用一份源，
工程 Define `PLAYER_ID=1/2` 区分），Beep.h 走共享 `MCU\inc`（工程已含该 Include Path）。
485 中转板（`main_hub.c`）**不修改**：它在电脑旁，与无线接收端同类。

### 4.5 编译后烧录要点

- 型号 STC15F2K60S2、频率与 `SysClock`（11.0592MHz）一致；
- 烧完关闭 STC-ISP，避免占用 COM 口影响游戏/串口测试工具。

## 6. 代码侵入性核对（"不能影响已有功能"如何保证）

1. 音效全部集中在 `sound_effect.c`，对外仅 4 个函数；main 只在**事件回调末尾或
   按下瞬间**并行追加 `Sound_Play(...)` 调用，不插入任何延时/阻塞；
2. 主循环仍只有 `MySTC_OS()`；所有发声都是 BSP 非阻塞 `SetBeep`（约 1µs 返回），
   10ms 回调单次执行 <1µs，满足 BSP"回调累计 <1ms"铁律；
3. `SOUND_ENABLED=0` 时模块编译为空操作（不含 `Beep.h`、不初始化蜂鸣器），
   任何调用都不产生代码；接收端工程连 `sound_effect.c` 都不加入，双保险；
4. 编译宏可整体关闭：把工程 C51 Define 写成 `SOUND_ENABLED=0`，所有板立即退回原行为。

## 7. 如何扩展/自定义

- **改某个音效**：改 `sound_effect.c` 顶部的 `sndToneList[]`（频率、`ms10`=时长/10）
  与 `sndPrio[]`（优先级）；时长必须是 10ms 整数倍。
- **加新音效**：表尾追加音步 + `sndStart/sndStepNum/sndPrio` 各加一项 + 头文件加 ID。
- **PC 串口指令触发"击中/被击中/结束"**：手柄已在收 PC 下行血量帧（AA D1/D2 HP），
  按血量下降沿自动触发被击中/结束音（已内置）。若 PC 新增专用事件命令（如"本车命中敌人"），
  在收到命令处调用 `Sound_Play(SOUND_HIT)` 即可；无线发送端 HEX-A 目前无下行通道，
  该端只响本机按键音（开火/移动），这是链路单向决定的，符合"手边板"范围。

## 8. 常见问题（FAQ）

| 现象 | 排查 |
| :--- | :--- |
| 编译报 L16 UNCALLED SEGMENT | BSP 库（STC_BSP.lib）内未调用模块的链接提示，**原有工程同样存在**（仓库 README 已说明无害）；本模块代码本身 0 告警 |
| 编译报 can't open 'Beep.h' | 无线工程 inc 自包含无 Beep.h：从 `MCU\inc` 复制一份，或把 `..\..\MCU\inc` 加进 Include Path |
| 烧录后完全没声音 | ① `SOUND_ENABLED` 是否为 1（接收端板除外）② 是否接了限流电阻且阻值过大 ③ 蜂鸣器跳线/插针是否闭合 ④ STC-ISP 烧录频率与 11.0592MHz 是否一致 ⑤ main 是否在 `MySTC_Init()` 前调用了 `Sound_Init()` |
| 声音太响/发刺 | 按第 3 节换更大电阻（680Ω→1kΩ）；音量档低档位对应大电阻 |
| 声音太轻 | 换更小电阻（470Ω→330→220→100Ω）或直连 |
| 10ms 回调冲突 | 若工程日后另有 10ms 逻辑，把 `Sound_Tick()` 并入既有 10ms 回调，不要在 `enumEventSys10mS` 上重复注册（sys 每个事件只保存一个回调） |
| 想整板静音 | 工程 C51 Define 写 `SOUND_ENABLED=0` 重新编译 |
| 按键"哒"声慢半拍 | 属 BSP 限制：正在响的旧音会自然响完再接新音（见 2.5），最长滞后约 200ms（被击中音场景），可接受 |
| 移动键嗒嗒频率不对 | 移动音由 100ms 按键采样触发，100ms 一声为本设计目标 |
