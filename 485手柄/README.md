# 485 三板手柄方案（主推）

把旧"两块手柄板各自用一根 USB 直连 PC"改为 **RS-485 总线 + 第三块中转板**：

- 两块**手柄板**（485 从机）只接 485 总线，不再直连 PC 数据；
- 第三块**中转板**（485 轮询主机）每 100ms 依次点名两块手柄，收到按键应答后
  经板载 USB（串口1）**原样转发给 PC**；
- **PC 端上行 3 字节协议零改动**：两块玩家从同一个 COM 口以 ~100ms 一包
  交替上报，PC 按"包内容自动绑定玩家"照常工作；v2.8 起 PC 另经同一 COM 下行
  `AA D1/D2 HP` 血量帧，中转板在总线空闲窗口转发给对应手柄驱动 **LED 血量条**。

```
[手柄1板]──┐                              ┌─ UART2/485 轮询主机 ─┐
[手柄2板]──┼── RS-485 共享总线(A/B/GND) ──→│  中转板(第三块板)      │── USB/串口1 ──→ PC
 每100ms采样  9600bps 8N1 半双工          │  点名P1→收→点名P2→收  │   9600bps 8N1
 被点名才应答                             └── 校验后原样转发 ──────┘   (1 个 COM 口)
```

## 三块板固件（HEX 统一在根目录 `HEX\`）

| HEX 文件 | 编译工程（`485手柄\`） | 用途 / 烧到哪块板 | 数码管身份 | LED（v2.8 起为血量条） |
|---|---|---|---|---|
| `485_Player1.hex` | `RS485_Handle1.uvproj`（源 main_handle.c） | **485 手柄1**（玩家1 从机，点名码 E1） | **1** | L0~L5 血量条（默认全灭） |
| `485_Player2.hex` | `RS485_Handle2.uvproj`（源 main_handle.c） | **485 手柄2**（玩家2 从机，点名码 E2） | **2** | L0~L5 血量条（默认全灭） |
| `485_Relay.hex` | `RS485_Hub.uvproj`（源 main_hub.c） | **中转板**（485 轮询主机 + USB 转发 PC） | **C** | 转发成功时 L0 亮（工作指示，非血量） |

- 两块手柄共用同一份源 `main_handle.c`，工程 C51 Define 分别写 `PLAYER_ID=1` / `PLAYER_ID=2`；
- 三个工程与 MCU 工程**共享同一份 BSP**：头文件 `..\MCU\inc`、库 `..\MCU\STC_BSP.lib`；
- 工程 Output 指向 `..\HEX\`，编译即产出上面三个 HEX（本机 Keil UV4 命令行实测
  三工程均 **0 Error**，警告仅为 BSP 库内未调用段 L16，无害）。

## 板间轮询协议（手柄↔中转板，对 PC 透明）

485 总线 9600bps、8 数据位、1 停止位、无校验，半双工。所有帧固定 **3 字节**
（保证总线字节流按帧对齐，点名回声/应答互不干扰）：

| 方向 | 帧内容 | 说明 |
|---|---|---|
| 中转板 → 手柄1 | `AA E1 00` | 点名玩家1（0xE 前缀与玩家号 0x01/0x02 永不冲突） |
| 中转板 → 手柄2 | `AA E2 00` | 点名玩家2 |
| 手柄1 → 中转板 | `AA 01 mask` | 应答，**与 PC 协议完全一致**（mask=按键位掩码） |
| 手柄2 → 中转板 | `AA 02 mask` | 同上 |
| 中转板 → 手柄1 | `AA D1 HP` | **下行血量帧（v2.8）**：玩家1 血量 0~3，空闲窗口转发 |
| 中转板 → 手柄2 | `AA D2 HP` | **下行血量帧（v2.8）**：玩家2 血量 0~3，空闲窗口转发 |

按键掩码：bit0 左转 / bit1 右转 / bit2 前进 / bit3 后退（按住持续）；
bit4 开火（K1，单发）；bit5 重开请求（K2，单发，PC 结算画面处理）；
bit6 K3（单发，PC 开始界面"任意键开始"用，对战中忽略）。

**下行血量帧（LED 血量联动，v2.8）**：PC 把 `AA D1/D2 HP` 写入中转板 COM
（USB/串口1）→ 中转板缓存 → 在 485 总线**空闲窗口**（本轮点名/应答结束 ≥20ms，
每 10ms 至多一帧）把同一帧广播到总线 → 只有命令码与本板匹配的手柄按血量刷新
**LED(L0~L5) 血条**：满血3=6灯、每掉 1 血灭右侧 2 灯、死亡全灭；其余板按码过滤
不应答。D 前缀与玩家号 01/02、点名码 E1/E2 永不冲突；不占用轮询时序
（空闲窗口远大于 100ms 周期所需，下行帧不挤占点名/应答带宽）。

**时序**（中转板每 100ms 一个周期，10ms 事件做超时计数，全部非阻塞）：
t=0 点名 P1 → 收到应答即转发并点名 P2（无应答 30ms 后也点名 P2）→
收到 P2 应答转发，周期结束。单块手柄掉线不阻塞另一玩家，缺包与否由
**PC 侧 0.6s 心跳超时**判定（画面顶部橙点"断开!"，输入冻结，恢复后自动回来）。

## 硬件接线

> 各板"485 接口"端子标识以板面丝印为准（通常 A/A+、B/B-，另需 GND 共地）。

1. **485 总线**：三块板的 485 A 并 A、B 并 B，成一条总线（A1-A2-A3，B1-B2-B3）；
2. **共地**：三块板 GND 相连（若都经 USB 由同一电脑供电则已天然共地，仍建议显式共地）；
3. **终端电阻**：总线最远端两端各加一个 **120Ω** 电阻跨接在 A/B 之间
   （看板面是否有 485 终端电阻跳线/焊盘；短距离桌面演示可先不加，不通再补）；
4. **供电**：中转板 USB 必须接 PC（唯一数据口）；两块手柄板板载 USB 仅作供电
   （充电头 / 充电宝 / PC 其它 USB 口均可）。
   > 若手柄用 PC 供电：会多出两个"静默 COM"（板子不发数据），游戏画面里只是
   > 灰色"未绑定"点，不干扰；介意可在启动参数里 `--p1 中转COM --p2 中转COM` 精确限定。

## 烧录

1. STC-ISP：型号 **STC15F2K60S2**，频率 **11.0592MHz**（外部晶振，与 `SysClock` 一致）；
2. 手柄1 板载入 `HEX\485_Player1.hex`、手柄2 板载入 `HEX\485_Player2.hex`、
   第三块板载入 `HEX\485_Relay.hex`；
3. 上电验证身份：三块板数码管最左位分别 **1 / 2 / C**；两块手柄 LED 默认全灭
   （v2.8 起 LED 为血量条，不再亮 L0/L7 身份灯）；
4. 烧完 **关闭 STC-ISP**（否则 COM 被占，游戏打不开）。

## 联调与验收

```bat
:: 1) 单独验证"手柄→中转→PC"链路（不关游戏也能跑）
cd PC
python tools/serial_probe.py            :: 应交替看到 玩家1/玩家2 的包，~10Hz 各一包

:: 2) 开游戏
python main.py
```

对照 README 验收清单 1~8 逐条跑（操作与旧 USB 直连方案完全相同：
导航键移动转向、K1 开火、命中扣血 +10 分、生命归零胜负、障碍阻挡、
结算后 鼠标点击 / 任一手柄按 K2 重开；验收8 = 手柄 LED 血量条：开局满血 6 灯、
被命中灭 2 灯、血包回血补亮、死亡全灭、重开复位——LED 亮灭需真板确认，
下行帧已由 `acceptance_sim.py` 自动化预演）。另验断线场景：
- 拔**手柄1** 的 485 线 / 断电 → PC 顶部玩家1 变橙"断开!"且输入冻结，玩家2 不受影响；插回自动恢复；
- 拔**中转板** USB → 两玩家同时"断开!"；插回自动恢复。

## 设计要点速查（改代码前必读）

- 手柄端：100ms 回调**只采样**（导航按住位 + K1/K2/K3 单发标志，逻辑与旧有线
  `MCU/main.c` 一致）；UART2(485) 收包按帧第 2 字节分发：收到"本板点名码"帧
  （AA E1/E2）才组包应答（应答请求被 Uart2Print 接受后才清单发标志 → 单发不丢不重）；
  收到"本板血量命令码"帧（AA D1/D2）只刷新 LED 血条不应答；其它帧（他人点名/
  他人应答/他人血量）按码过滤丢弃。接收匹配头放宽为单个 0xAA，由回调分发。
- 中转板：轮询时序常量集中在 `main_hub.c` 顶部
  （`P1_WAIT_TICKS=3`→30ms、`P2_WAIT_TICKS=4`→40ms，10ms 计数单位，可调；
  v2.8 新增 `DL_SEND_TICKS=2`：空闲 ≥20ms 才允许发下行帧）；
  转发前查 UART1 空闲，避免覆盖发送队列；下行帧由 `myUart1Rxd_callback` 接收、
  `my10mS_callback` 的空闲窗口逐帧转发（一 tick 至多一帧，不碰撞点名/应答）。
- 所有业务都在事件回调内（10ms/100ms/收包），无阻塞等待，符合 BSP 铁律
  （`while(1){ MySTC_OS(); }`，回调累计 <1ms）。
- 点名码 E1/E2、血量命令码 D1/D2 与按键帧 `AA 01/02 xx` 永不撞帧；本板点名回声
  与别的手柄应答/血量帧均按码过滤，不会误应答/误转发。

## FAQ / 排障

| 现象 | 排查 |
|---|---|
| serial_probe 完全无包 | 三块板身份数码管是否 1/2/C；485 A/B 是否接反（对调一试）；是否共地；波特率是否 9600；STC-ISP 是否已关闭 |
| 只看到玩家1（或2） | 对应手柄板是否上电；其 485 线是否接触良好（该玩家在游戏里会变橙"断开!"） |
| 偶发掉包/坦克一顿一顿 | 检查总线接线质量与共地；两远端 120Ω 终端电阻补齐；桌面短距离可先不加电阻验证 |
| 游戏里多出灰点 | 手柄板用 PC USB 供电产生的"静默 COM"，无害；可用 `--p1/--p2` 指定中转板 COM |
